# בדיקת תקינות נתוני GPS (GPRMC)

הפרויקט קורא משפטי NMEA מסוג `$GPRMC` ממודול ה-GPS (Microstack L80),
ומוודא שכל מדידה תקינה לפני שהיא נכנסת לרשימת המדידות. הקובץ [src/main.py](src/main.py)
מכיל את כל הלוגיקה.

## דוגמה למשפט GPRMC

```
$GPRMC,013732.000,A,3150.7238,N,11711.7278,E,0.00,0.00,220413,,,A*68
```

השדות (מופרדים בפסיקים) הם: סוג המשפט, שעה (UTC), סטטוס, קו רוחב, כיוון קו רוחב,
קו אורך, כיוון קו אורך, מהירות בקשרים, כיוון תנועה (מעלות), תאריך, שני שדות
תזוזה מגנטית (בד"כ ריקים), ומחוון מצב (mode indicator) — ולבסוף checksum אחרי ה-`*`.

## איפה נעשות הבדיקות

### `validate_checksum(gps_line)`
בודקת רק את השורה הגולמית, לפני כל פירוק לשדות.

**מה זה בודק:** עושה XOR על כל התווים בין ה-`$` לבין ה-`*`, וממיר לערך הקסדצימלי.
משווים את התוצאה לשני התווים שאחרי ה-`*` (ה-checksum שה-GPS עצמו שלח).

**למה זה חשוב:** אם הייתה שגיאת תקשורת (רעש בקו הסיריאלי, ניתוק באמצע שידור וכו')
ה-checksum לא יתאים, וכך יודעים שהנתונים לא אמינים בלי צורך לבדוק כל שדה בנפרד.

### `is_valid_gprmc(gps_line)`
זו הבדיקה "הראשית" שמרכזת את כל התנאים לפני שמשתמשים במדידה. מריצה קודם את
`validate_checksum`, ואז ממשיכה בבדיקות הבאות (בסדר הזה, ויוצאת מיד עם `False`
ברגע שאחת נכשלת):

1. **מספר שדות = 13** — משפט RMC תקין מכיל בדיוק 13 שדות. אם השורה נחתכה
   (למשל התנתקות באמצע שידור), המספר לא יתאים.
2. **סוג המשפט הוא `$GPRMC` או `$GNRMC`** — מוודא שזה אכן משפט RMC ולא סוג
   אחר של משפט NMEA שבטעות הגיע לפונקציה הזו.
3. **סטטוס = `A`** — ה-GPS עצמו מדווח `A` (Active) כשיש לו נעילת לוויינים תקינה,
   ו-`V` (Void) כשאין. אם הסטטוס `V`, שאר השדות (קו רוחב/אורך) לא אמינים בכלל.
4. **כיוונים תקינים** — קו הרוחב חייב N או S, קו האורך חייב E או W. כל ערך אחר
   מעיד על שדה פגום.
5. **אורך שדות זמן/תאריך** — שדה השעה חייב להיות באורך 6 תווים לפחות (HHMMSS),
   ושדה התאריך בדיוק 6 (DDMMYY). תופס שדות ריקים או קטומים לפני שממירים אותם למספר.
6. **המרה תקינה למספרים** — קו רוחב, קו אורך, מהירות וכיוון תנועה חייבים
   להיות ניתנים להמרה ל-`float`. אם לא — השדה פגום.
7. **טווח ערכים הגיוני** — קו הרוחב חייב להיות בין 0 ל-9060 וקו האורך בין 0
   ל-18060 (בפורמט `ddmm.mmmm` של NMEA — מעלות כפול 100 ועד 59.9999 דקות).
   ערך מחוץ לטווח מעיד על שדה שהתפרש לא נכון.

רק אם **כל** התנאים האלה עוברים, `is_valid_gprmc` מחזירה `True`.

### `parse_gprmc(gps_line)`
**לא בודקת כלום** — מניחה שהשורה כבר עברה את `is_valid_gprmc`, ורק מפרקת אותה
לשדות ומחזירה `dict` אחד עם המדידה (זמן, קו רוחב/אורך, מהירות בקמ"ש, כיוון, תאריך).

### `GPSLog`
האובייקט שמצטבר לאורך זמן. `add(gps_line)` מריץ קודם את `is_valid_gprmc` על
השורה שהתקבלה, ורק אם עברה — מוסיף את המדידה המפורקת ל-`self.readings`.
כך `readings` תמיד מכיל רק מדידות שעברו את כל הבדיקות למעלה.

### `GPSLog.to_html(path="gps_data.html")`
כותב את כל המדידות שנצברו לקובץ HTML עם טבלה (ורענון אוטומטי כל 2 שניות),
כדי שאפשר יהיה לפתוח אותו בדפדפן ולראות את הנתונים בצורה נוחה במקום כטקסט גולמי.

## שימוש

```python
from src.main import GPSLog

log = GPSLog()
log.add("$GPRMC,013732.000,A,3150.7238,N,11711.7278,E,0.00,0.00,220413,,,A*68")
log.to_html()  # יוצר/מעדכן gps_data.html
```

או להריץ ישירות ולהזין שורות אחת אחת עד `quit`:

```
python3 src/main.py
```
